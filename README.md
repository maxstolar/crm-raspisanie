# Расписание школы CRM-маркетологов Mindbox

Одна вертикальная веб-страница со скрытым редактором. Ни сборки, ни бэкенда:
редактор публикует правки прямо в этот репозиторий через GitHub API.

**Адрес:** https://mindbox.ru/storage/raspisanie-shkoly-crm/
**Редактор:** тот же адрес с `#edit`, пароль в `EDIT_PASS` (см. ниже)
**Тестовая копия:** тот же адрес с `?test` — черновик следующего потока

## Структура

```
assets/
├── index.html         ← страница и редактор целиком (шрифт, лого, вёрстка вшиты)
├── data.json          ← основное расписание, правится через редактор
├── data-test.json     ← тестовое расписание, появляется после первой публикации в тест
└── avatars/           ← фото спикеров и workshop.png
```

На витрину идёт **содержимое** `assets/` — оно раскладывается в корень адреса.
То есть `assets/data.json` открывается как `/storage/raspisanie-shkoly-crm/data.json`,
а `assets/avatars/x.png` — как `/avatars/x.png`. Вложенного `/assets/` на витрине нет.
README и прочее в корне репозитория на витрину не попадают.

## Как это устроено

Расписание хранится не в вёрстке, а в JSON. Страница ищет его по цепочке
и останавливается на первом источнике с годными данными:

1. `data.json` напрямую с `raw.githubusercontent.com` — свежие данные, кэш GitHub ~5 минут
2. копия `data.json` на витрине — страховка, если GitHub недоступен; отстаёт до часа
3. расписание, вшитое в `index.html` в блоке `schedule-data` — если не открылось ничего

Поэтому опубликованные правки видны через несколько минут, а не через час:
часовая синхронизация подрядчика тащит только саму страницу, но не данные.

Кнопка «Опубликовать» коммитит JSON в этот репозиторий через Contents API.
Если запрос не прошёл, страница честно объясняет причину и скачивает `data.json`,
чтобы его можно было залить в репозиторий руками.

Время во всех сообщениях коммитов — **московское** (UTC+3). Раньше писалось UTC,
из-за чего у публикующих из других поясов день около полуночи получался вчерашним.

## Отмена правок и откат публикаций

**Вернуть опубликованное** — отменяет правки на странице и возвращает расписание,
которое прямо сейчас видят студенты. В репозиторий ничего не пишет. Если не ответили
ни GitHub, ни витрина, подставляется расписание, вшитое в страницу, и редактора
об этом предупреждают — оно заморожено на сентябре–декабре 2026 и может быть устаревшим.

**История** — список последних 20 публикаций `data.json` с датой, автором и сообщением
коммита. Заливки из теста помечены отдельно, текущая версия — как «сейчас на сайте».
Выбранная версия загружается в страницу для просмотра; на сайте ничего не меняется,
пока не нажать «Опубликовать». Состав версии (сколько месяцев и занятий) показывается
после загрузки, а не в списке: иначе пришлось бы скачивать все 20 версий разом.

Важно понимать, что **каждый клик по «Опубликовать» — отдельный коммит**, поэтому
«предыдущая версия» обычно означает то же расписание без одной исправленной опечатки,
а не прошлый релиз. Из-за этого история сделана списком с датами, а не кнопкой
«шаг назад»: нужную точку выбирает человек.

Если, пока вы выбирали версию, кто-то успел опубликовать свою правку, публикация
отменится с объяснением — чтобы старая версия не затёрла чужую работу. История
читается и без токена (репозиторий публичный), так что остаётся рабочей, даже
если токен истёк.

## Тестовая копия для следующего потока

Добавьте `?test` к адресу — например `…/raspisanie-shkoly-crm/?test#edit`.
Появится жёлтая плашка сверху, а расписание будет читаться и писаться
в отдельный файл `data-test.json`. Основное расписание при этом не затрагивается,
у черновика в браузере свой ключ хранения, студенты теста не видят.

**Пока `data-test.json` не создан, тест открывается полностью пустым** — без месяцев
и занятий, с подсказкой на месте расписания. Так и задумано: у нового потока свои
месяцы, и начинать удобнее с чистого листа, а не вычищать прошлый.

В режиме теста в панели редактирования появляются две кнопки:

- **Взять из основного** — заполнить тест текущим основным расписанием, если
  всё-таки нужно править от него. В репозиторий ничего не пишет, только в страницу
- **Залить в основное** — перенести то, что на странице, в `data.json`.
  Спрашивает подтверждение и показывает состав: сколько месяцев и занятий.
  Это и есть публикация теста в прод «по кнопке»

Пустое расписание залить в основное нельзя — кнопка откажется, чтобы случайный
клик в свежем тесте не обнулил живое расписание. «Сбросить» в тесте очищает всё
до пустого листа, а не возвращает вшитое расписание, как в основном режиме.

Отдельная копия репозитория и второй токен для этого не нужны: страница одна,
поэтому тест и прод не могут разъехаться по вёрстке.

## Аватарки

Требования к файлам и карта «кто есть кто» — в `assets/avatars/README.txt`.

Фото можно загрузить **прямо из редактора**: в панели дня есть поле «Фото спикера».
Файл любых пропорций приводится к PNG 120×120 (кадрируется как в вёрстке —
по центру по горизонтали и от верха) и коммитится в `assets/avatars/`.
Имя файла берётся из поля «файл», а если оно пустое — транслитерируется
из фамилии: «Трофим Рудзий» → `rudziy`.

Фото уходит в репозиторий сразу при выборе файла, отдельно публиковать не нужно.
Картинка ищется сначала на витрине, при промахе — напрямую в GitHub, поэтому
только что загруженное фото видно сразу. Если файла нет нигде, показываются инициалы.

HEIC с айфона браузер не открывает — редактор про это скажет и попросит JPG или PNG.

## Токен GitHub

Редактор пишет по fine-grained personal access token с правом
`Contents: Read and write` только на этот репозиторий.

**Токен истекает 15 января 2027.** После этой даты публикация молча перестанет
работать — кнопка будет сообщать, что токен недействителен. Перевыпустить:
https://github.com/settings/tokens?type=beta (fine-grained, only this repository,
Contents: Read and write), затем заменить части в `GH_TOKEN_PARTS` в `index.html`.

**Токен разбит на три части и склеивается в рантайме.** Это не защита: страница
публичная, собрать его обратно может любой, кто откроет исходники. Смысл в другом —
GitHub сам сканирует публичные репозитории на свои токены и автоматически отзывает
найденные, а Push Protection может заблокировать коммит. Если вписать токен одной
строкой, он умрёт в первые минуты. Первый разрез делайте внутри префикса
`github_pat_`, чтобы разбить и его.

Риск открытого токена принят осознанно: ценность данных низкая, права ограничены
одним репозиторием и только записью файлов, git даёт полную историю — любую
порчу видно и можно откатить через `git revert`. Пароль редактора в этой схеме —
удобство, а не защита: раз токен в коде, проверку пароля можно обойти.

Полезно включить уведомления на push (Settings → Notifications), чтобы узнать
о посторонней записи сразу.

## Пароль редактора

Строка `const EDIT_PASS='…'` в `index.html`. Меняется в одном месте, перезапускать
нечего — коммит и подождать синхронизацию.

## Витрина и домен

Доменом и витриной управляет подрядчик: он забирает содержимое `assets/`
из этого репозитория примерно раз в час и раскладывает по адресу выше.
Прямого доступа к его инфраструктуре нет, со стороны страницы настраивать нечего.

Из этого следуют две разные задержки, которые полезно не путать:

| Что изменили | Когда видно |
|---|---|
| Расписание (`data.json`) | несколько минут — читается напрямую из GitHub |
| Фото спикера | сразу — при промахе витрины берётся из GitHub |
| Саму страницу (`index.html`) | до часа — ждём синхронизации подрядчика |

## Что не решено

Репозиторий и токен живут на личном GitHub-аккаунте — если владелец уйдёт,
публикация останется без присмотра. Правильное решение — перенести репозиторий
в корпоративный аккаунт Mindbox, когда появится доступ, и перевыпустить токен
оттуда. Перенос сохраняет историю, но потребует поменять `GH_OWNER` в `index.html`
и попросить подрядчика сменить источник синхронизации.
